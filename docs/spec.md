# 仕様

## 1. 目的・背景

- 応用情報技術者試験の午後DB問題は、DBの理解を深めるのに役立つ。ただし過去問だけでは問題数が少なく、すぐに解き終わってしまう。
- 午後DB問題のような演習を、もっとたくさん解けるようにする。
- 使った人に、楽しみながらDBの理解を深めてもらう。

## 2. 利用者

- DBを学び始めた初学者全般。

## 3. 対象範囲

- 当面: ER図の穴埋めのみ。
- 将来: 関係スキーマ、SQL、正規化など、午後DB問題全体へ広げる。問題の種類を後から足しやすい設計にする。

## 4. 機能要件

### 4.1 問題

- 1問は「業務の説明文」「ER図」「解答群」「解説文」で構成する。
- 画面には説明文とER図を並べて表示する。
- ER図はIE記法（多側を鳥の足の線で表す）で描く。
- ER図の配置は固定（ドラッグで動かせない）。
- 空欄にできる要素は、当面はエンティティ名と属性名のみ。

### 4.2 解き方

- 解くだけならログインは不要。
- 答え方は選択式のみ。解答群の選択肢をドラッグ＆ドロップで空欄にはめる。
- 解答群は問題全体で1つ。空欄の数より多めに選択肢を入れる。
- 同じ選択肢を複数の空欄に使える。

### 4.3 答え合わせ

- 空欄ごとの正誤、正解、解説文を表示する。
- 採点はサーバー側で行う。正解と解説は答え合わせの後にだけ返す。
- 解答結果（どの問題の、どの空欄が正解だったか）を記録する。ログインしていない人の解答も記録する。

### 4.4 問題の作成

- 最初のサンプル問題は管理者が作り、DBに登録する。
- 将来は、ログインしたユーザーがアプリ内の作問画面で作れるようにする。解説文は作った人が書く。

### 4.5 難易度・評価（MVPの次）

- 難易度は、解いた人の結果（正答率など）から決める。解かれた回数が少ないうちは「未判定」と表示する。
- 解いた人が★1〜5で問題を評価できる。評価できるのはログインした人のみ。

## 5. 非機能要件

- 端末: PCのブラウザが対象。当面は、画面幅が狭いとき（スマホなど）に「PCで開いてください」と表示して使えないようにする。
- 公開: 当面は開発者のPCで動かすだけ。公開先はMVPが固まってから決める。
- データ: 問題と解答結果はPostgreSQLに保存する。PostgreSQLはPCに直接インストールしたものを使う。

## 6. MVPの範囲

1. 問題一覧画面
2. 問題画面（説明文、IE記法のER図、解答群からのドラッグ＆ドロップ）
3. 答え合わせ（正誤、正解、解説）
4. PostgreSQLへの保存と、サンプル問題数問
5. 解答結果の記録（難易度の表示はMVPの次）

MVPの次に作るもの: ログイン、作問画面、★評価、難易度の表示。

## 7. API

詳細は [API設計](design/api.md) を参照。

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/health` | 死活確認 |
| GET | `/api/questions` | 問題一覧（新しい問題が上） |
| GET | `/api/questions/{id}` | 問題本体（説明文、ER図、解答群。正解・解説なし） |
| POST | `/api/questions/{id}/attempts` | 回答（空欄ID → 選択肢ID）を採点・記録し、正誤、正解、解説を返す |

- リレーションシップの線を引く問題（カーディナリティを含む）
