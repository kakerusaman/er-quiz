# 仕様（たたき台）

## 目的

ER図を見ながら、空欄になったテーブル名・カラム名を埋めて、データベース設計の読み方を練習できるようにする。

## MVP（いまの雛形でできること）

- 問題を1つ表示する（サンプル: ECサイトの users / orders）。
- テーブルはドラッグで動かせる。リレーションは線とカーディナリティ（1:N など）で表示する。
- 空欄は選択肢から選ぶ。「答え合わせ」で空欄ごとの正誤（緑/赤）と点数を表示する。
- 問題はサーバーのメモリ上にある。正解はクライアントに送らない。

## API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/health` | 死活確認 |
| GET | `/api/questions` | 問題一覧（id, title） |
| GET | `/api/questions/{id}` | 問題本体（正解なし） |
| POST | `/api/questions/{id}/answers` | `{"answers": {"b1": "email"}}` を採点して `{"correct": {...}, "score", "total"}` を返す |

## 次にやること（候補）

1. 問題一覧画面と、複数問題の切り替え
2. PostgreSQL に問題を保存する（`quiz.Store` の実装を追加。sqlc の採用を検討）
3. 空欄の種類を増やす: カーディナリティ、PK/FK、リレーションの線をドラッグでつなぐ
4. 問題作成画面（ER図を描いて空欄にする箇所を指定）
5. 採点履歴の保存
